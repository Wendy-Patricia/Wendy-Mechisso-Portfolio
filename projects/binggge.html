Binggge

A web application for discovering TV shows and building a personal watchlist, powered by TVMaze and PostgreSQL.

JavaScript Node.js Express PostgreSQL Vite

Case study

Entertainment / Web

Overview

Binggge is a responsive TV series tracking application built with JavaScript, Vite and CSS, supported by an Express API and PostgreSQL database. Users can search for series through TVMaze, explore synopses and episodes organised by season, and manage a private watchlist. The interface is in French.

Context

Binggge is a personal web application developed incrementally. It brings show discovery and watchlist management together in one place.

Problem

Finding a show is only part of the experience. Users also need a simple way to keep track of titles they want to watch and retrieve their list later.

My contribution

I developed and integrated the frontend and backend features, including series search, clickable cards, synopses, episodes organised by season, and personal watchlists. I replaced username-only identification with password-based authentication and secure sessions, improved accessibility and error handling, and added automated tests. I also refined the GitLab CI pipeline and configured deployment with Docker and PostgreSQL, troubleshooting database initialisation, credentials and API routing.

Technical approach

I kept the frontend lightweight with vanilla JavaScript, Vite and CSS, separating API requests, state, views, search and focus management into small modules. Search uses debounce and request cancellation to prevent outdated results.

The Express API connects to TVMaze for series and episode information and PostgreSQL for accounts, sessions and watchlists. Passwords are protected with salted scrypt hashes, while sessions use HTTP-only cookies. Private database queries are scoped to the authenticated user.

used semantic HTML, keyboard navigation, focus management and accessible status messages throughout the interface. Testing combines isolated API tests, frontend tests and focused Playwright flows. Docker handles compilation and deployment, with GitLab CI running automated checks.

Catalog pagination is handled in the frontend, showing six search results per page. Search starts empty and runs when the user submits a query.

Challenges

The main challenges were replacing username-only identification with secure authentication, ensuring each account could access only its own watchlist, and handling loading states and API failures clearly. Other challenges included preventing outdated search results, making clickable cards and modals accessible, simplifying CI tests, and resolving database configuration issues during deployment.

Result

The application now supports password-based registration, login and logout, private watchlists, watched-status filters, series details and episode synopses. Search uses debounce and protection against outdated responses. Automated API, frontend and browser tests cover the main flows, while Docker provides a consistent build and deployment process.

What I learned

I learned how to connect frontend behaviour with backend security, protect passwords using salted hashes, and manage sessions through HTTP-only cookies. I also developed practical experience with accessible interfaces, asynchronous requests, isolated testing, GitLab CI and Docker deployment. Troubleshooting the server taught me that rebuilding containers does not automatically update database schemas or stored credentials.
